FREQUENTLY ASKED QUESTIONS

Questions, without the fine print.

The important things to know before sending or receiving a file with SendZero.

Who can decrypt my file?

Anyone who has the complete share link, including the part after #. Treat that link like a secret.

Does SendZero receive the decryption key?

No during normal operation. The key is kept in the URL fragment after #, and browsers do not send that fragment to the server in HTTP requests.

Can SendZero see the filename or file contents?

The filename, MIME type, metadata and file chunks are encrypted in your browser before upload. The server still sees technical metadata such as transfer ID, sizes, timestamps, node and request information.

What happens if I lose the full share link?

SendZero cannot reconstruct the decryption key for you. Without the complete link, the encrypted file cannot normally be decrypted.

How large can a file be?

The current limit is 5 GiB per file. Files are split into 8 MiB chunks so the browser does not need to keep the entire file in memory.

Can an interrupted upload be resumed?

Yes. Select the same local file again in the same browser. SendZero can reuse the local upload state and send only missing encrypted chunks while that upload session is still valid.

Can an interrupted download be resumed?

Yes in supported Chromium-based browsers using the File System Access API. Other browsers may use streaming or Blob fallbacks that do not support resume after a browser restart.

What does one-time download mean?

After the first successfully completed download, the encrypted server copy is deleted. An interrupted authenticated download can still resume instead of consuming the transfer immediately.

Can I delete a transfer before it expires?

Yes. The sender receives a separate private delete capability. Use Delete transfer now or the Recent transfers panel in the same browser.

What is stored under Recent transfers?

Only local sender-side information needed to revoke recent transfers, including the transfer and node IDs plus the delete capability. This list stays in that browser and disappears when browser storage is cleared or entries expire.

What happens when a transfer expires?

Its encrypted server copy is removed by cleanup and the share link stops working. SendZero is a temporary transfer service, not a backup service.

Why can an upload or download be temporarily limited?

SendZero applies abuse, concurrency, disk-capacity and download-traffic limits so one anonymous user or link cannot exhaust the service for everyone else.

Do I need an account?

No. Sending and receiving files does not require registration or a SendZero account.

How do I report an abusive transfer?

Email abuse@sendzero.link with the SendZero transfer URL and a clear description. Do not include the decryption key unless it is necessary for the report.
