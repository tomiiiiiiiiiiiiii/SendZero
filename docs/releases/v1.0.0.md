# SendZero v1.0.0

This is the first public 1.0 release of SendZero: an open-source, zero-access file-sharing service that encrypts files in the browser before upload.

## What is included

- AES-256-GCM client-side encryption via Web Crypto.
- Encrypted filenames, MIME types and metadata.
- 8 MiB chunked transfers with a 5 GiB logical file limit.
- Resumable uploads.
- Resumable large downloads where the File System Access API is available.
- One-time downloads.
- Sender revoke/delete capabilities.
- Local Recent transfers recovery without accounts.
- Database-free multi-server storage.
- Direct browser-to-storage-node transfer.
- Rate limiting, egress controls and disk emergency stops.
- Multi-node admin CLI and production preflight checker.
- English, German and Polish UI.
- FAQ, Terms, Privacy Policy and a private vulnerability-reporting process.
- CI checks for PHP 5.6, PHP 8.2 and JavaScript.
- Full Git-history credential/configuration audit.

## Security model

For each transfer, the browser generates a random 256-bit AES key. Files and metadata are encrypted locally. The recipient key is kept after `#` in the share URL, so browsers do not include it in normal HTTP requests to the SendZero backend.

The server still sees operational metadata needed to run the service, including encrypted payload size, chunk count, timestamps, selected storage node and normal request/network metadata.

See `README.md`, `SECURITY.md` and `docs/PRODUCTION.md` for the full model and deployment guidance.

## Release validation

The deployed HTTPS instance at https://sendzero.link/ has completed the documented production checks for the core transfer path, including a full 5 GiB end-to-end transfer with matching SHA-256, interrupted upload/download resume, one-time deletion, sender revoke, cleanup/expiry, abuse and egress limits, disk emergency-stop behavior, admin operations and security-header checks.

**Important:** SendZero has not undergone an independent security audit. The tests above are operational validation and automated release hygiene, not a formal audit or guarantee of security.

## Deployment

Before exposing a self-hosted instance publicly:

1. create `config.local.php` from `config.local.example.php`;
2. keep `DATA_DIR` outside the public web root;
3. configure HTTPS and the documented security headers;
4. schedule `cleanup.php` on every storage node;
5. run `php sendzero-preflight.php https://your-host.example`;
6. review `docs/PRODUCTION.md` and `docs/TESTING.md`.
